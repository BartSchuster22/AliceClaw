## PSI platform build references

### Fixed decisions (never revisit during build)
- MVP excludes PSI internals.
- MVP excludes marketplace.
- VPS provider: Hetzner only.
- Payment provider: Stripe only.
- Installation templates: one per product.
- Referral rewards: subscription credit only, no cash payouts.
- User accounts: individual only, no teams or organisations.
- White-labelling excluded.

### Subscription lifecycle policies
- Renewal payment failure: 3-day grace period; emails on day 1 and day 3; day 4 suspend subscription and power off server; after 14 days suspended delete server and set expired; reinstatement powers server back on and returns subscription to active.
- User cancellation: service continues to end of paid period; warning email 48h before period end; at period end delete server and set subscription cancelled.
- Provisioning failure after payment: set subscription to provisioning_failed; no automatic refund; admin retries manually; if unresolved within 48h, manual Stripe dashboard refund.
- Plan upgrade/downgrade: excluded from MVP; UI says contact support.

### Architecture principles
- Billing uses internal normalised events only: subscription.activated, subscription.renewed, subscription.payment_failed, subscription.cancelled, subscription.grace_period_ended.
- BillingProvider interface only: createCheckoutSession, cancelSubscription, getSubscription.
- StripeAdapter implements BillingProvider; nothing outside billing imports Stripe SDK.
- VPS abstraction uses VpsProvider interface only: createServer, getServerStatus, deleteServer.
- MockVpsAdapter for dev/test with fake IPs and fake status after 8 seconds.
- HetznerAdapter for production; workers never call Hetzner directly.

### Credentials tiers
- Tier 1: one-time OpenClaw app password generated during provisioning, emailed once, never stored, never retrievable.
- Tier 2: provisioning root SSH private key stored only in env var PROVISIONING_SSH_PRIVATE_KEY, never in DB/API/logs.
- Tier 3: user SSH public key optional during onboarding, injected via cloud-init, preferred production access model.

### Delivery email rules
- Must include instance IP, OpenClaw URL, one-time app password, and immediate password change instruction.
- Must never include root credentials, SSH private keys, or server-level access.
- Clear one-time password from worker memory after email send.

### Admin model
- Admin roles enum: super_admin, support_admin, billing_admin, content_admin, provisioning_admin, referral_admin.
- Middleware: requireAdminRole(allowedRoles: AdminRole[]), returns 403 when unauthorized.
- Route permissions:
  - user management: super_admin, support_admin
  - billing: super_admin, billing_admin
  - CMS: super_admin, content_admin
  - provisioning queue: super_admin, provisioning_admin
  - referral management: super_admin, referral_admin
- Use only super_admin on day one.

### CMS hard scope
- Exactly six CMS keys only: hero_headline, hero_subheadline, hero_cta_text, product_card_footer_note, faq_entries, footer_tagline.
- faq_entries is JSON array of {q, a}.
- No rich text editor, no media upload, no page builder.

### Provisioning state machine
- States: queued -> creating_server -> server_ready -> provisioning -> completed.
- Failure from any state -> failed.
- Retry from failed -> queued, admin-initiated only.
- Idempotency: at start of creating_server, query vps_instances by subscriptionId; if found, skip creation.
